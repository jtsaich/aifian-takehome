# 07: 修改截止點、待確認與品項後台

**What to build:** 有兩種修改不會直接生效：過了修改截止點、又會影響生產的修改，以及疑似單號重複使用。這兩種會進到待處理頁，由總部人員確認或退回，處理結果在門市下一次上傳時告訴她。總部也在後台維護品項清單、品項別名和截止天數。

**Blocked by:** 05（角色登入）、06（修改偵測與分類）

**Status:** ready-for-agent

- [ ] 修改截止點是取貨日前 N 天。N 預設 7，總部可以在後台調整。
- [ ] 過了修改截止點的影響生產的修改，一律變成待確認；資料更正照常直接套用。
- [ ] 疑似單號重複使用一律變成待確認，不管有沒有過截止點。
- [ ] 待處理頁顯示這些資訊：修改類型、舊值→新值、哪家門市、哪一次上傳。總部人員在這頁確認或退回，系統記錄是誰處理的。
- [ ] 確認之後，修改才套用；退回之後，系統沿用修改前的內容。
- [ ] 門市重傳一模一樣的修改時，不重複建立待確認，只在回覆裡提醒：
  - 還在等處理：寫「仍待總部確認」。
  - 已經被退回：寫「已被總部退回，系統仍以 80 盒計算，請把 Excel 改回 80」。
  - 門市把 Excel 改回原本的數字之後，這則提醒就不再出現。
- [ ] 總部的處理結果，附在該門市下一次上傳的回覆最前面。不用 push。
- [ ] 總部可以新增品項和品項別名。補上別名後，門市重傳一次，原本不收的列就會收進來。
- [ ] 上面這些操作，只有總部人員可以做。
- [ ] 自動化測試要涵蓋：
  - 截止點的邊界：剛好是第 N 天。
  - 被退回之後重傳。
  - 確認之後重傳。
