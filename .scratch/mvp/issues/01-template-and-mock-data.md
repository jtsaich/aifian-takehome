# 01: 範本與模擬資料

**What to build:** 做一份門市拿到就能直接用的統一範本，以及整個 demo 需要的模擬檔。全部都是可以直接打開檢查的檔案，也是後面每張 ticket 驗收時的對照組。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 範本是 .xlsx，一列就是一筆訂單明細。
  - 訂單層欄位：單號、訂購人姓名、電話、接單日、取貨日、宴客日、新人姓名、接單人。
  - 明細層欄位：品項、盒數、備註、狀態。
  - 品項和狀態用下拉選單，狀態只有「取消」一個選項。
  - 門市代碼和範本版本放在固定的儲存格。
- [ ] 商品清單約 6–8 款喜餅，其中幾款要有品項別名。範本的下拉選單和之後的解析共用同一份清單。
- [ ] 6 家門市各一份模擬上傳檔，資料全部是假的。每家至少混進一種典型錯誤，以下每一種都要有門市分到：
  - 漏單號
  - 日期用民國年
  - 品項用別名
  - 同一個單號的各列，訂單層欄位不一致
  - 取貨日已經過了
  - 多了一個自己加的欄位
  - 多了一個「備忘」分頁
- [ ] 一組「第二天」的模擬檔，涵蓋：
  - 追加、減量、改取貨日、取消、資料更正
  - 過了修改截止點的修改
  - 疑似單號重複使用
  - 跟前一天完全相同的整份重傳
- [ ] 2 家門市各一份舊格式的 Excel，欄位跟範本不同、也沒有單號欄，給歷史資料匯入用。
- [ ] 產生器可以重跑：
  - 同一個 seed 一定產生同樣的檔案。
  - 日期以執行當天為基準往前後推算，哪一天跑 demo 都合理。
- [ ] 附一份對照表，逐一列出每個檔案混進了哪些錯誤、系統應該怎麼回覆。後面的 ticket 拿這份表當驗收依據。
