# 06: 修改偵測與分類（修改截止點之前）

**What to build:** 門市重傳檔案，或改過 Excel 再傳時，系統自動判斷每張單屬於哪一種：新單、沒變，或是某一種修改。判斷完就套用，並留下修改紀錄。總部可以看到每張喜餅訂單完整的修改歷史。依照 ADR 0001，檔案裡沒有出現的單，系統一律不處理。

**Blocked by:** 04（欄位檢查、欄名放寬與多分頁）

**Status:** ready-for-agent

- [ ] 內容完全沒變的訂單明細，系統不做任何事，回覆裡也不提。
- [ ] 修改類型要自動判斷：追加、減量、改取貨日、取消（看狀態欄）、資料更正。同一次修改可以同時屬於好幾類。
- [ ] 要能認出「疑似單號重複使用」。這張 ticket 只負責標出來，待確認的流程在 07。
- [ ] 修改紀錄要記下：哪一次上傳、哪位傳檔者、時間、哪個欄位、舊值、新值。紀錄只能新增，不能改寫。
- [ ] 回覆的寫法，例如：「單號 0123：追加，喜餅 A 80→120 盒」。
- [ ] 稽核頁可以查任何一張喜餅訂單的完整修改歷史。
- [ ] 自動化測試：從檔案裡刪掉一列，不會被當成取消。
- [ ] 自動化測試：01「第二天」那組檔案的回覆，跟對照表一致。
